## 1. Set up the PC

**You need:** Node.js **22.18 or newer** and Git. Python 3 is only needed on the VPS. Nothing else has to be
installed for the world itself.

> The commands below are written for macOS/Linux terminals. If the PC runs **Windows**, tell me: setting an
> option for one command (`NAME=value npm start`) is written differently in PowerShell, and I'll give you the
> Windows versions.

### 1.1 Get the code

```bash
git clone https://github.com/ggclips153-dot/ggclips-oauth.git
cd ggclips-oauth
git checkout claude/ai-agent-world-build-xxy71v
cd world
npm install
npm test          # should end with: fail 0
```

### 1.2 The real world (not the demo)

Logins for the bots are created once. Each command prints the bot's token **once**; store each token in that
bot's secrets.

```bash
npm run profile -- add --id marc --role owner --label Marc
npm run profile -- add --id dm --role dm
npm run profile -- add --id bob --role architect
npm run seed                                   # the starting cities (safe to re-run)
npm run profile -- add --id mayor-<city-id> --role mayor --city <city-id>     # one per Mayor
npm run profile -- add --id hermes-gateway --role gateway                     # the shared-surface check (see 3.4)
npm run user -- add --username marc --profile marc                           # your dashboard sign-in
npm start                                      # http://127.0.0.1:8787
```

To bring the ledger over from somewhere else instead, copy `data/world.db`, `config/profiles.json` and
`config/users.json` into the same places before `npm start`. The server checks the whole ledger's hash chain
at start and refuses to run if it's broken.

### 1.3 The demo world (safe to play with)

```bash
npm run demo          # builds data/demo.db once (delete that file to rebuild it)
npm run demo:start    # http://127.0.0.1:8787, sign in: marc / demo-password-123
```

In the demo, a stand-in plays the DM and the Mayors, so everything reacts. The real world is never touched.

### 1.4 StarNet stations (one per city, A20)

```bash
cd ~ && git clone https://github.com/androoAGI/starnet.git && cd starnet && npm install
```

Then start the world with `STARNET_DIR` pointing at it:

```bash
STARNET_DIR=~/starnet npm start          # or: STARNET_DIR=~/starnet npm run demo:start
```

Each city gets a station on ports 8801 and up. Choose a model provider inside each station the first time
(OpenRouter key, a supported sign-in, or Ollama), or give all of them one OpenRouter key with
`STARNET_OPENROUTER_KEY=<key>`. The downloaded StarNet app from starnetos.com is **not** needed.

### 1.5 The shared memory surface (A21)

On the **VPS** (next to `surface.db`), run the read-only reader `vps/surface_reader.py`, or install
`vps/surface-reader.service`:

```bash
SURFACE_READER_TOKEN=<openssl rand -hex 32> SURFACE_READER_HOST=$(tailscale ip -4) \
  SURFACE_DB=/home/hermeswebui/.hermes/mnemosyne_shared/surface.db python3 surface_reader.py
```

On the **PC**, add `SURFACE_URL=http://<VPS Tailscale IP>:8765 SURFACE_TOKEN=<the same token>` when starting
the world. If the surface names cities differently from the world, copy `config/surface-cities.example.json`
to `config/surface-cities.json` and map them.

### 1.6 All settings

| Setting | Default | What it does |
|---|---|---|
| `WORLD_PORT` / `WORLD_HOST` | `8787` / `127.0.0.1` | where the dashboard listens (keep it local; reach it through Tailscale) |
| `WORLD_DB` | `data/world.db` | the ledger |
| `WORLD_COOKIE_SECURE` | on | set `0` only for plain `http://` from another machine |
| `DM_WEBHOOK_URL` / `DM_WEBHOOK_SECRET` | unset | rings the DM on each of Marc's requests (signed) |
| `STARNET_DIR` | unset | StarNet's source folder: turns on one station per city |
| `STARNET_BASE_PORT` | `8801` | first station port |
| `STARNET_OPENROUTER_KEY` | unset | one model key for every station |
| `SURFACE_URL` / `SURFACE_TOKEN` | unset | the read-only shared-surface reader on the VPS |

Files that are private and never committed: `config/profiles.json`, `config/users.json`,
`config/secrets.json`, `config/starnet.json`, `data/`.

## 2. What exists today

**The world and its rules.** Cities, districts and departments, and agents created only at a city's college,
then assigned to a department. Professors and deans, the lifecycle from enrolled to senior, KPI and task
strikes, jail, the economy (credit for real revenue only), and the World Constitution. Every change is an
entry in the hash-chained ledger.

**A19: you never wait.** Everything you do in the dashboard applies at once, carried out as you
(`marc-as-dm`, `marc-as-mayor`) through the same rules as the bots.

**Dashboard pages**
- **Map**: world map and 3D globe.
- **City**: the StarNet station (when on), Details, and the 3D city. Jump to the college, a district or a
  department. Rename or delete districts and departments (deleting asks twice).
- **Live**, **Security**, **Inbox**, **Economy**, **Constitution** and **Activity**.
- **Social**: a Vista Social-style planner for Instagram, Facebook, TikTok and YouTube.
  - A calendar with drag to reschedule, approvals, a unified inbox, analytics with CSV export, and channels.
  - Hashtags and a first comment on every post.
  - An agent's post you reject goes to "Sent back to agents" with your reason, and comes back revised for
    approval.
  - Nothing is published without your approval. Posting is by hand ("Mark as posted") until each platform's
    developer keys are added.
- **Talk to an agent**: click any agent's name, or a person in the 3D city. With a running station the answer
  comes from StarNet; otherwise from the city's Mayor bot.
- **Memory**: the shared surface, read-only, with each agent's latest status, KPI pulses and every note with
  its four tags. Limited by the spec's matrix: you see every city plus WORLD; a Mayor sees its own city plus
  WORLD.

## 3. What the bots connect to (for the DM and the Mayor bots)

Bots call the world's API with `Authorization: Bearer <token>`. The full list is in the README ("API").

### 3.1 Requests from Marc
- Each of Marc's requests is an `intent.*` event. With `DM_WEBHOOK_URL` set, the DM gets a signed ping for
  each one (`x-world-signature: sha256=<hmac>`).
- Since A19, Marc's requests are already carried out when they arrive. The ping tells the DM about them;
  there's nothing left to route.
- A message to a Mayor (`intent.message_mayor`) and a message to an agent (`intent.message_agent`) are routed
  to `mayor:<city>`.

### 3.2 Talking to agents
- If a city has no running StarNet station, its Mayor bot answers as the agent.
- The answer is posted as `agent.said`, with:
  - `subject` = the agent's world ID
  - `text` = the answer
  - `replyTo` = the seq of Marc's message

### 3.3 Social
- **An agent's draft:** the city's Mayor writes `social.agent_drafted`, with `channelIds`, `text`, and
  optionally `title`, `media`, `firstComment` and `tags`, plus `authorAgentId` (a graduated agent of that
  city) and an optional `note`.
- **Rework after a rejection:**
  - `GET /api/social/rejected` lists posts Marc sent back, with his reason.
  - The rework is `social.agent_revised`, with `postId` and the changed fields.
- **What happens on the platforms:** the DM (or a platform bot) reports these:
  - `social.inbox_received` for comments, messages and mentions
  - `social.metrics` for daily numbers
  - `social.post_published` or `social.post_failed` (only ever for a post Marc approved)

### 3.4 The shared surface
- **Before an agent writes a note:** Hermes asks `POST /api/surface/check` (the `hermes-gateway` login) and
  writes only on `allow`. See `docs/SURFACE-GUARD.md`.
- **Tag mechanism (the Messenger's call):** Mnemosyne's stock shared-remember tool accepts only its own
  kinds (meta, preference, correction, identity) and has no city, dept or agent fields. The reader takes the
  four tags from either:
  - the note's **metadata**: `city`, `dept`, `agent`, and `kind` (one of the spec's eight), or
  - a first line in the note: `city=… dept=… agent=… kind=…`

  Please settle this before agents start writing, so every note carries all four tags.
